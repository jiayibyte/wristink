## 1.2.0 日月升落与天气联动

太阳和月亮使用独立的地平线可见性，不再按“白天太阳/晚上月亮”固定二选一。有效缓存位置下，SunCalc v1.9.0 近似公式按 UTC 计算高度角、时角与月相；太阳参考 Garmin 官方日出日落区间，月亮按自身高度角升落，月相由日月相对位置计算。图标轨迹映射到表盘天空并被山脊遮挡，非精确方位图。没有位置时使用明确的本地时段/月相示意，不主动启动 GPS。

固定云已从所有山景底图移除。晴天强制零云，少云/多云绘制独立云层；阴雨雪雾分别切换山体配色、积雪或能见度，雨雪按对应天气出现，厚云遮住日月。四种光照与五种天气山体组合按需加载一个背景。云缓慢变化，天文状态按分钟更新，天气/位置读取保持 5 分钟缓存；AMOLED AOD 仍只显示低亮时间。

天文回归基于未修改的 SunCalc v1.9.0 生成独立数值样本，覆盖北京、纽约、悉尼、赤道与极地，原生太阳高度、月亮高度、月相与照明比例误差均在断言容差内。Instinct 2S / Instinct 3 Solar / epix2 各 16 项测试通过，另覆盖日出/落顺序、跨午夜、极昼极夜、位置缺失回退、晴天零云、天气山体变化和原有配置数据逻辑。许可证、算法范围与参考样本见 `assets/astronomy/`。

雪天首次全尺寸原生预览暴露了逐像素云层绘制触发 Watchdog 的问题（失败截图 `dist/evidence/sky-snow-watchdog.png`）。已替换为原生圆形图元，在单色设备上增加小尺寸透明前景遮罩恢复山脊遮挡；优化后 epix2 与 Instinct 2S 雪天重新实际运行并导出正常截图，首次绘制后分别剩余 75,440 B 和 14,544 B；这是单次画面余量，不是长时间峰值测试。数值测试通过不替代完整画面性能验证。最终构建保留类型检查并启用官方 `--no-gen-styles` 选项；部分目标仍有 Rez.Styles 优化提示，原始日志已保留。

当前 `sky-sunrise.png`、`sky-noon.png`、`sky-fullmoon.png`、`sky-snow.png` 是实际模拟器 framebuffer，使用固定演示日期和数据。日出/正午/满月晴空图在云层优化前捕获，因云量为零，优化不影响该绘制路径；雪天截图是修复后重新捕获。模拟器设置编辑器未能载入临时演示面板，因此改用独立应用 ID 的固定时间样本；这些演示属性不进入正式包。

最终六个目标 PRG 重新构建成功，`dist/build-live.json` 保留结果。当前预览只使用这轮明确选取的六张原生截图；旧 fēnix 图片不混入 1.2.0 的预览包。

- 午夜、中午、12/24 小时制与系统设置回退。
- 缺失、过期、未来时间戳；心率无效值。
- 黎明/黄昏边界、缺失太阳事件时的画面回退。
- 智能场景优先级、手动覆盖、关闭智能场景。
- 零值、负海拔、公英制与温度换算、缺失值占位。
- MIP 休眠不画秒、唤醒失效整帧；epix2 不执行该 MIP 专项断言。
- 圆窗默认心率与月相周期范围。

早期测试捕获了旧设备不支持浮点 `%` 的月相异常，已用 `floor` 周期归一修复。测试夹具分别使用新旧 BufferedBitmap API。测试运行器在结果为 PASS 时仍返回退出码 1，本项目根据 SDK 的明确测试结果行判断，并保留原始退出码。

最后一轮测试通过后只做绘图坐标、MIP 颜色量化和预览 ID 隔离，未改变时间/数据/场景选择逻辑；对应画面已重新运行检查。

## AMOLED 低亮

通过官方模拟器 Settings → Display Mode → Always-On 实际进入低亮模式，捕获 `epix2-aod.png`，并恢复 High Power。该帧仅 1,384/173,056 像素点亮，约 0.80%。正常山景与数据栏被清除，时钟低亮显示；代码按实际分钟在四个间距大于字体高度的纵向区域轮换。单帧比例不代表所有时间的最高亮屏率或真机烧屏认证。
