# 数据、内存、性能与省电

具体数据入口、单位、权限、当前值与历史回退见 [佳明官方数据接入手册](official-data.md)。先核实来源语义，再决定刷新频率。

## 状态表先于优化

为 awake、MIP sleep、AMOLED AOD、settings changed、cache lost 列出读取源、周期、重画区域与失效条件。

- 通常系统低功耗按分钟更新；抬腕进入高功耗。若用户要求抬腕才走秒，休眠路径不要做一秒回调工作。
- 用户确实需要持续秒时，可考虑 MIP 的 `onPartialUpdate`，只刷新小区域，并验证设备电源预算和超预算降级。不要在该路径读设置、加载资源、请求天气或扫描历史。
- 缓存天气/日出/位置；时间回拨、位置有效性、时区变化、无数据和过期要有明确行为。不要把旧历史心率装成当前传感器实时值。续航天数只用系统估计，不能从电量百分比随意换算。
- 比较显示值后再触发局部刷新；注意分钟、天气分类和定位像素变化等缓存键。
- demo有独立ID或编译开关；live缺失值显示占位，不能回填演示位置或心率。正式产物排除诊断入口及健康/定位日志。

## 内存与热路径

记录首次绘制、资源加载峰值、换皮肤/字体、连续抬腕、睡眠切换后的 freeMemory。留出项目适用余量；Retro World曾采用8KiB门槛，不能视为所有手表/功能足够。短8帧诊断只是冒烟测试，不证明长期无泄漏。

优先降低同时驻留资源数：当前皮肤而非所有皮肤、所需字符集而非全字库、静态底图加小动态区。重用固定数组，避免每纬线/每秒分配多边形与临时对象。计算复杂度与绘图面积分别测量。以设备可支持的调色板/透明槽验证资源，不把“少颜色”盲目等同于安全。

Connect IQ踩坑：
- `createBufferedBitmap` 的引用需要保留，用时取 `.get()`；缓存丢失时重建。旧 `new BufferedBitmap` 能力不同，用 `has` 分支而不是只看API标签。
- 旧 BufferedBitmap 可能没有 `getWidth/getHeight`，需要 `getDc()` 获取尺寸。不要把所有位图类型当同一接口。
- MIP透明槽与旧Venu自定义调色板路径曾报错；原生默认调色板是经验证的兼容回退，现代彩色缓存才用匹配的有界调色板。
- clip、penWidth、颜色是共享状态。AOD绘制前显式恢复1px笔宽，否则上一帧指针的粗笔会擦掉大部分细线。
- 缓存命中与资源读取次数必须实际计数。CPU耗时来自主机模拟器，不可直接推算实表续航。

## AMOLED AOD

按目标当前官方约束设计低亮、少像素、按分钟更新的独立布局；主时间仍须可读。减少常亮静态元素并移动；仅“每分钟位移”不保证所有物理像素都休息，要对全部时间/连续窗口验证交集。旧设备与新设备烧屏保护能力不同，检查当前指南和运行时。

Retro World的轮廓时间+像素轮休通过预算检查，但点划状外观可能太碎，不能把它作为每款设计的默认美学。可比较较小的实心字、连续细线或更疏的信息；先验证实际1×可读性，再检查亮屏比例。不要为了低数字占比把时间做得读不清。

诊断序列应包含首次进入、唤醒多秒、分钟跨界、午夜、数据缺失、设置/主题切换、天气变化、位置变化、进入/退出AOD及更长循环。正常退出诊断，不在单次回调塞入大量帧触发看门狗。
