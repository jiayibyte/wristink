# Garmin 商店版本提交与证据

## 产物准备

沿用当前授权和仓库隔离/交付入口。Git 提交、PR合并、商店上传、审核及公开可下载分别记录，不互相替代。技能本身不赋予 main 合并或商店发布授权；已有适用的会话授权无需重新询问。

从明确提交取得正式 IQ 包，记录版本、manifest AppID、商店 ID、SHA-256、SDK、目标及硬件变体覆盖。核对正式包排除 demo/diagnostic、密钥和真实用户数据。复用前比较文件哈希与已有验证记录；一致且源代码/配置未变时，不重复整套构建。文件不匹配或有相关新修改才重建。

IQ 可能是7z：先识别格式，按格式解包到临时目录；通配提取子目录下的 `*-settings.json` 时使用递归选项。原包不重写。使用 Garmin SDK 的 `VerifyingUtils.verifyIqFile` 验证签名，不能用普通全文件 OpenSSL 摘要代替。哈希只证明文件一致，不能证明签名或运行正确。

验证强度见 [验收](validation.md)。共享运行代码、区域 API、资源生成或设置覆盖变更通常需全目标/全硬件变体构建，加代表性原生运行；小范围布局只需对应设备验证，正式发布仍需确认所宣称兼容范围的导出包。

准备中英文更新说明；已改变的主描述也要同步，例如旧说明“仅抬腕走秒”不能留在持续刷新版本。保留无关价格、地区、通知、隐私及设备迁移设置。新截图来自实际实现并注明模拟数据；不上传用户的健康或精确位置截图。

## 两阶段网页流程

优先已有足够能力的连接器；没有时用当前允许的浏览器工具。读取该工具的上传文档，文件选择通常通过 `waitForEvent('filechooser')` 后点击可见上传控件，再 `setFiles` 指定绝对路径。不要硬编码旧 accessibility 索引或不存在的上传 API。

1. 从正确应用的 **Upload New Version** 进入，检查标题、商店ID、当前 latest version；选择已验证 IQ 并填版本号。若后台已记录目标版本，先核对是否已提交，不重复上传同一版本。
2. 页面可能显示“提交即同意 Developer License Agreement and Terms of Use”。按当前工具要求处理法律确认：先把两款包、版本和文案备好，再一次性确认所需的本次提交；已取得本次适用确认后不重复询问。发布请求不自动授权新账号、新权限或其他法律承诺。
3. 点击 **Upload and publish** 后等待文件验证。确认 **Status: Verified / Signature: Verified / Version** 和正确 manifest ID。按钮名称不代表已经完成整个发布。
4. 到 **Edit App Details**，填写各语言的更新说明和必要描述/截图，核对现有免费/区域等设置，再完成 **Submit**。首次上传按钮通过后仍未做此步，是未完成流程。
5. 等待提交结束并核对状态。失败或中断时先读取当前页面；不因为没有立即跳转就再次点 Submit。被动等几秒后读取新状态即可，不密集重载尚在提交的页面。

工具安全拒绝时说明具体动作和原因，尝试允许的更窄路径或补充真实授权证据；若仍拒绝，停在那个动作并请求明确授权。不用原始 HTTP、其他浏览器表面或替代工具绕过拒绝。

## 发布状态分层

| 可见证据 | 能报告什么 | 不能据此报告什么 |
|---|---|---|
| 文件和签名 Verified | Garmin 接收并验证了候选包 | 已完成详情提交或公开 |
| Submit 完成，文案出现 | 详情提交完成 | 新二进制已对用户开放 |
| 后台 Latest app version 为目标版本 | 后台已记录该新版本 | 国际/中国公开页已同步 |
| 应用卡 Status: Approved | 该卡显示应用已批准 | 本次新二进制已批准，除非版本关联明确 |
| What’s New 正文写2.1.0，页面 Version仍2.0.0 | 文案更新，公开版本字段仍旧 | 把手写说明当真实已上线版本 |
| 公开版本字段/可用下载对应新版本 | 所检查区域已显示/提供新版本 | 所有区域、所有用户立即可更新 |

详情页旧版本但提交完成时，可打开 **Upload New Version** 只读查看 `Latest app version`；不要选择文件或再次提交。保存新版本证据后取消空表单。2026-11 曾出现后台已记录新版本、公开页仍旧而说明已新，具体传播时间没有保证，不能擅自把它称为“审核中”。

在后台和公开信息矛盾时进行一次有目的的刷新/后台核对，仍不一致就分别记录。不要无依据反复上传、提高版本号或承诺几分钟内生效；用户未要求持续监控时不创建轮询自动化。中国区另读公开页面，没有中国区身份不代表国际上传失败，也不声称已直接发布到中国区。

## 交付记录

保存包哈希、版本、提交日期/地区、文件验证、后台 latest version、公开版本字段、文案语言和截图路径。每款/每区独立记录，可用 JSON；不使用单个 `released=true` 混淆所有状态。

最终简报给应用链接、目标版本、后台确认和公开同步状态；完成网页登录写操作后按当前工具要求保存并展示截图。只有分别确认上传和详情 Submit 完成，才能说“已上传并提交，公开开放尚未确认”；恢复任务中仅见后台 latest 时，报告“后台已记录目标版本，详情提交状态尚待核实”。对本次测试只报告实际完成的验证，不补写真机成功或续航结论。
