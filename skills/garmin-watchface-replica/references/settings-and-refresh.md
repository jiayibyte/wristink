# 配置、持续秒与区域兼容

## 可配置数据区

以当前布局的数据槽为单位定义稳定 property key、默认值、可选指标和隐藏值，不把布局坐标或内部实现选项暴露成普通用户设置。已有键及含义要兼容旧安装。用户说“所有数据项能调整”时先覆盖现有槽位，额外指标由实际 API 与布局空间决定，不自动承诺系统全部健康评分。

- 使用一份配置定义生成 properties、settings 和中英文字符串；校验读取值的类型、范围及旧配置回退。
- 区分系统格式、强制12小时、强制24小时；测试午夜/中午、单数字小时、`00:00`、`12:00`、`23:59`。AM/PM 与数字墨迹分区，前导零作为独立选择；不要靠全局缩字体解决拥挤。
- 数据槽换源后同时更换标签、单位和图标。隐藏项不应残留旧值或无关太阳/天气图标。窄槽优先省略标签、紧凑单位或显示明确占位符，避免越界和无说明截断。
- `onSettingsChanged` 重读配置，失效整帧、地图、环境/太阳等受影响缓存，并请求更新；关闭某个读取源时解除不再需要的订阅。不要在每秒回调读取持久化设置。
- 检查打包后每个硬件变体的设置 JSON：键集合、默认值、选择值、类型、中英文以及默认语言回退。XML 正确不等于全变体都已包含。
- 测试默认/英文/简体中文及一个未专门翻译的语言。需要英文回退时，让默认资源为英文、中文覆盖保留中文；不强制用户把整只手表改成英文作为唯一长期解决方案。

参考：Retro World 的 `FaceSettings.mc`、`DataFields.mc`、`tools/settings.py`、`tools/check_settings_package.py`；Moke 的资源生成器与 `scripts/check-iq-package.py`。这些是可复用代码，不是固定要求必须具有21项或94项设置。

## 刷新状态和功耗

Garmin 系统决定抬腕高功耗窗口，不能通过表盘计时器保证“抬着腕就永久高功耗”。在支持局部更新的 MIP 设备上，用 `onPartialUpdate` 实现持续秒；AMOLED 的低亮 AOD 单独处理，不把 MIP 策略直接移植。

| 路径 | 工作 |
|---|---|
| 唤醒/整分钟/设置改变 | 必要数据与资源准备，缓存时分针、刷新静态内容 |
| 同分钟秒级更新 | 只读需要的系统当前心率，比较变化；擦旧秒针小框、画新针，更新改变的秒数字；仅重画含心率的槽 |
| MIP 休眠局部更新 | 图形使用已有缓存和 clip；只有目标 API 允许且预算验证通过时才读取当前心率并按变化绘制，否则保持正常周期的缓存；不读天气、不扫历史、不加载资源、不计算地图 |
| AMOLED AOD | 低亮、像素休息及分钟刷新；按设备当前约束验证 |
| 超预算/缓存失效 | 使用设备允许的降级策略；缓存无效时等待安全的完整刷新，不在受限回调重建复杂资源 |

`onPowerBudgetExceeded` 属于 **WatchFaceDelegate**，不是仅在 WatchFace 中定义同名函数就会收到通知。把代理和视图一起从 `getInitialView` 返回。降级后何时重试应明确且可测试，不能每秒无限重试。

读取心率每秒一次不等于传感器每秒生成新样本。秒级路径不要重复遍历历史；历史回退保留原始样本时间并检查过期、未来时间和时钟回拨。全帧回调跨分钟时不要拿旧时分针缓存执行局部刷新。

原生验证覆盖：抬腕→睡眠→跨分钟→再次唤醒、关闭秒针/数字秒、换心率槽、设置生效、预算回调。模拟器进入实际低功耗模式后确认持续变化，记录 Watchface Diagnostics 的原始数值及其单位来源；不把未经确认单位的数值换算成实表耗电。原生测试直接调用回调只是行为测试，不替代真实调度/预算验证。

官方入口：[WatchFace](https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/WatchFace.html)、[WatchFaceDelegate](https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/WatchFaceDelegate.html)。实现时核对安装 SDK 与目标固件，不把本页描述当作所有设备承诺。

## 区域 API 与日出日落

同一个 SDK device 的 `compiler.json` 可包含多个 `partNumbers`。基础能力取所有目标变体 `connectIQVersion` 的最小值；不要只信 `deviceGroup`。2026-11 本能2/2S曾出现国际3.4.2、区域3.2.7，太阳接口从3.3开始，未经保护的调用是明确兼容风险，但不能直接认定每条 IQ 评论都源于它。

用 `scripts/sdk_device_baseline.py path/to/compiler.json` 提取区域基线，缺失/非法版本应报错，不默默采用宣传版本。最低 API 生成策略加运行时 `has` 与 null 检查；保留每个硬件最低固件，不为通过构建伪造 manifest 版本。

日出日落优先官方 API 与有效位置。接口不存在时才按产品需求使用有出处的近似算法，例如 [NOAA 太阳公式](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)；官方返回 null 也可能是极昼极夜，不应无条件用另一算法覆盖。验证纬度范围、闰年、极区、跨 UTC 日期和手表时区，标明近似性。

手动经纬度是显式可选来源：默认关闭，验证范围，开关关闭时不能把默认0,0当用户位置；开启后只影响声明的地图/太阳计算，不伪造对应城市天气。日期、时区、位置变化及设置修改都应失效太阳缓存。位置与健康数据不输出到发布证据。
