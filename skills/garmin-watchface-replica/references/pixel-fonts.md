# 像素字体与小图形：从“能显示”到“看得清”

新表盘建字体、或收到“字体锯齿、发虚、小字看不清”的反馈时读本篇。视觉拆解与必看字符见 [视觉与字体](visual-fidelity.md)，这里只讲字形怎么造、怎么验。

## 先弄清这块屏能做什么

Connect IQ 的自定义字体是 BMFont：一个 `.fnt`（每个字符在图里的矩形、偏移、`xadvance`）加一张 PNG 图集。编译后是逐像素掩码，`dc.drawText()` 原样贴到屏幕上，**不缩放、不平滑**。PNG 里是什么像素，屏幕上就是什么像素，所以清晰度问题只能在生成 PNG 的那一步解决。

- `fonts.xml` 的字体默认按 1-bit 导入。要灰阶边缘必须同时满足：`antialias="true"`、PNG 的 alpha 本身带灰度、目标设备支持且内存够。三者缺一都是白做。
- 2 色屏（Instinct 系列等）没有灰阶，`antialias` 帮不上忙，清晰度完全来自字形构造。
- MIP 不等于 1-bit，先查设备位深再决定，见 [设备适配](devices.md)。

开工前决定走哪条路并记录原因：

| 方案 | 适合 | 代价 |
| --- | --- | --- |
| 系统字体（`Graphics.FONT_*`） | 想要原生观感的主时间、数字；布局能跟着字号档走 | 字号档位由固件定死且每个机型不同；中文取决于固件区域；`FONT_NUMBER_*` 只有数字；只能运行时调用，不能提取进自己的图集 |
| 自绘位图字体 | 跨机型尺寸统一、中文标签、按参考精确复现 | 每个尺寸都要构造并验证；占资源内存 |
| 混合 | 主时间用系统字体，标签和中文自绘 | 两套字的笔画重量要对齐 |

系统字体只存在于 SDK 设备包和真机里，没有 SDK 的机器出不了它的预览，这一点要提前告诉用户。

## 1-bit 字形的构造规则

1. **在目标像素网格上直接构造，不要把轮廓字体缩小后二值化。** 为抗锯齿屏设计的字体有任意角度的斜线和椭圆弧，阈值化后台阶必然不规则，这就是“锯齿感”的来源。
2. **笔画宽度是整数，全字库一致，竖笔落在整列上。** 奇数宽度的中心线在像素中心，偶数宽度的在像素边界。
3. **只用横、竖、45° 和等步长斜线。** 斜线画成等宽的横向游程逐行平移，步长按行数和列数均分；拐角用对称的切角或小圆弧。
4. **不做非等比拉伸。** 框的宽高比变了就重新构造，不要把同一个字形压扁塞进去。
5. **墨迹宽度不超过 `xadvance − 1`。** 粗体靠更高的字盒或更宽的字距，不靠描边外溢。用描边加粗会让墨迹比字距还宽，连排时全部粘成一团。
6. **笔画粗细按尺寸分段，不线性缩放。** 经验值：字高 8 以下 1px，9–18 用 2px，再往上约为字高的 10–12%。同时保证字腔至少 2px（2px 笔画时最好 3px）；不够时先给数字加宽一列，再考虑减笔画。
7. **钩、衬线这类端部细节只在字腔还有余行时保留。** 否则 9 会闭合成 8，2 的顶部会多出一个碗。
8. **小于 3×5 像素没有能区分十个数字的设计。** 不要让布局落到这个尺寸；避不开时在目标矩阵里标明，不要宣称已优化。
9. **汉字按笔画结构手工定位。** 先给横笔分配行、给竖笔分配列，保证相邻笔画之间至少空 1px。粗体只加粗竖笔（整体向右膨胀 1px），横笔之间的空隙才不会粘连。用奇数宽度，中竖才有真正的中心列。高度取数字字高加 1–2 行，并与数字的视觉中心对齐。
10. **数字用等宽盒。** 每个数字都按 0 的字盒构造，1 自己在盒内定位。按各自墨迹压缩会把 1 压成小写 l。

## 度量是契约

已发布字体的 `xadvance`、行框和图集坐标决定了布局和设置项的行为。优化字形时只换墨迹，度量逐项保持不变，并用检查脚本比对。新表盘则反过来：先定度量和字腔，再画字。

## 生成与验证流程

1. 列表：每个字体的用途、字符集、字高、`xadvance`、目标机型的缩放比。
2. 构造字形。WristInk 里可复用的起点是 `moke/scripts/pixel_glyphs.py`（笔画路径、等步长斜线、数字、单位字母、日期汉字），接入方式见 `moke/scripts/font_rasterizer.py` 的 `render_font`。它不经过 FreeType，所以不同 Pillow 版本下输出逐字节一致。
3. **每个缩放比各自重新构造**，不要缩放已有图集。把所有目标缩放比都跑一遍，而不是只看主机型。
4. 机器检查：
   ```sh
   python3 scripts/pixel_review.py atlas resources/fonts/data.fnt --out audit.json --one-bit
   ```
   它会报字格越界、数字缺失/空白/撞形、数字连排时相碰或重叠、1-bit 目标里混入灰度。再跑项目自己的字体和布局检查。
5. 看图。必须看**连排文本**而不是孤立的字格：数字串、日期、带单位的数值、最长星期。1× 判断可读性，4–6× 最近邻放大判断像素结构。再出整张表盘的改前/改后对比。
6. 模拟器截图和真机确认。前面几步只是筛查，不能替代这一步。

## 可切换的字形风格与配色主题

- **字形风格**：同一套度量（字距、字盒）下可以有多种构造：圆角、方角、七段数码管（细长六边形段、段间 1px 斜缝，笔画约为字高的 1/10）、5×7 点阵。墨刻的大时间用 `pixel_glyphs.digit(..., style=...)` 实现，新增风格只加字体族，不改布局。笔画粗度对七段要单独设：沿用轮廓字的笔画会把段压成菱形。
- **配色主题**：把双色精灵图（数字、字母、星期、天气图标、表盘刻度、地图）做成位图字体，字体按当前 `setColor` 着色，任何主题都不需要额外图片。面板用矢量圆角矩形按主题色绘制；需要合并的形状（如日期标签与时间面板）按层画：全部外框色 → 全部间隙 → 全部纸色，交界处才是一条连续边框。彩色 MIP 的主题色直接取 64 色调色板里的值。
- **彩色与 AMOLED 分开判断**：「有调色板可上色」和「AMOLED 常亮行为」是两个开关。用一个 `COLOR` 同时控制两者时，彩色 MIP 只能做成黑白（否则会被当成 AMOLED、失去局部刷新）。

## 自动缩字与圆屏排版

- 数据位按宽度自动选字号时，宽度不够会退到细笔画的小字号，同一行就出现一粗一细。给每个位置留够常见最长值（如"56%"、"100%"）在常规字号下的宽度，图标与文字的间距按图标实际宽度定，不要所有位置统一留大间距。
- 把方屏布局整体缩进圆屏的内接正方形（约 0.71–0.76 倍直径）会留下一大圈空黑边。按元素墨迹到圆心的距离检查：放大到约 0.86 倍直径，只把会碰到边框的几行（顶部、页脚、角落的圆窗）单独内移或缩窄；圆窗用独立的变换缩放和定位。改完在最小内存的圆屏机型上看剩余内存。
- 官方图标（如太阳能强度）没有可用字形时，按官方图案在 16px 网格上重画，不要把官方大图缩小阈值化；图标与文字的间距跟着图标宽度走。

## 多色屏与 AMOLED

同一套骨架可以输出灰度边缘：保留 alpha 灰度并加 `antialias="true"`，然后用实际截图评估可读性和内存。不要给 1-bit 目标输出灰度图集，编译器的阈值化结果不受你控制。

## 小图表

- 一个桶对应一个像素时不要直接逐点连线，采样抖动会变成一片毛刺。把坐标取整到整列；相邻两列之间用两段竖直游程连接，线条保持 1px 宽。
- 单桶抖动用 1-2-1 平均压掉，但等于最高值或最低值的点保持原样，否则曲线够不到刻度标的数。
- 最低值画在轴线上方 1px，不要和轴线重合。
- 刻度数字用同一套数字构造和等宽盒。
- 只调用项目 DC 包装层和测试替身已有的绘图方法；加新图元前先确认缩放包装和单元测试的替身都支持。

## 离线预览的可信度

离线预览从设置默认值和源码常量取值，不要写死某一版布局。默认设置改了而预览没跟上，预览就会展示一个不存在的界面。预览与模拟器截图不一致时先修预览。交付时标明“离线像素预览，非模拟器截图或真机照片”。

## 收到“锯齿/看不清”时的排查顺序

1. 目标屏幕的位深是多少？
2. `fonts.xml` 的 `antialias` 与 PNG 的 alpha 级数是否匹配目标屏幕？
3. 字形是不是由轮廓字体阈值化得到的？有没有非等比缩放？
4. 墨迹是否超出 `xadvance`，连排是否粘连？
5. 同一字体内笔画宽度是否一致？
6. 每个缩放比是重新构造的，还是缩放出来的？

第 3、4 条是 Moke 1.2.x 的实际病因，见 [两款表盘经验索引](project-patterns.md)。
