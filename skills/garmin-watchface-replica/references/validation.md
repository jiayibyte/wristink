# 视觉、运行与交付证据

## 三道独立验收

**视觉**：同一数据/时刻的参考裁图、原生模拟器截图、1×并排、4×最近邻局部。检查主时间重量/字形、区域比例、墨迹基线、边界、孔洞和图标一致性。原照片需记录透视校正。像素diff只比较已对齐同尺寸图；不要将动态数值差异算作布局缺陷。若参考与目标屏幕比例不同，按已声明的适配约定比较，不编造一个总还原率。

**行为**：真实时间12/24h、日期跨月、极值与缺失数据、天气分类、定位过期、日出日落跨午夜、awake/sleep/AOD、设置变更和缓存恢复。演示/正式分开。关键刷新逻辑测试放到Monkey C运行环境，不只在Python里模拟算法。

**预算**：全目标编译，加代表性原生运行。选择最小RAM、旧图形API、最高分辨率、圆/方屏、硬件圆窗、AMOLED各类。记录SDK、设备包、PRG哈希、最小剩余内存、读取/地图重建次数、耗时与警告。性能测试影响不能被摘要隐藏；耗电需实表长时测量。

## 工具使用

`pixel_review.py compare` 不自动对齐/缩放，输出原生并排、最近邻放大、差异图和区域差异数据。颜色差/截图光照可造成大量差异，所以指标不能当作审美评分。

`pixel_review.py atlas` 检查BMFont字格越界、十个数字缺失/空白/完全相同。它不会证明字形好看、排版居中或基线正确；必须看文字组合。透明atlas按alpha取墨迹，不透明默认按暗色墨迹，可用 `--ink light`。BMFont预渲染数据若颜色约定不同，应显式指定。

模拟器截图从File > Save Screen Capture取得，保存framebuffer原图；壳图另存。使用当前授权的UI工具操作。Mac模拟器无输出/旧窗口标题/锁屏时不算通过。只关闭本任务测试进程并按正常UI重启；先区分主机CoreAnimation/Metal崩溃和Monkey C异常。

## 发布可复现性

从干净检出可生成资源和编译；私钥、登录态、个人路径、真实健康/位置不进入PR。安装包与源码提交分别给证据，Git提交不能证明商店已上架。正式包排除demo和diagnostic；使用SDK验签器验证IQ，而不是假定所有签名都是PRG整个文件的普通摘要。IQ可能是7z，先识别格式。

只有用户要求发布时准备价格、语言、封面、原生截图与文案。以后台回执区分上传、待审和公开。自动发布不包含接受新条款的隐含许可；遵循当次工具规则。商店截图展示真实实现并标明演示数据，不用概念图掩盖实际像素问题。
